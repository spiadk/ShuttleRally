The rhythm of the game

Move. Read. Return.

01 / GET IN POSITION

Take the court

Choose a difficulty, tap Let’s play, then Serve. Drag across the lower court to move sideways and follow the lime landing marker.

02 / TIME YOUR SHOT

Wait for the ring

When the shuttle is near you and its ring lights up, tap Clear or Smash. Stay within racket reach. Use one finger to move and another to hit.

03 / KEEP IT GOING

Play the open court

A clear buys time; a smash travels faster. Returns aim crosscourt based on your position. Reach 11 with a two-point lead to win, or be first to 15.

Arcade rules: you serve every rally. Tap the upper-right pause button for a break. Leaving the app pauses play; tap Resume when you return. Your best rally is saved, but an active match resets if Android destroys the app process.

From source to court

Run in Android Studio

  1. Clone or download ShuttleRally. Open the project folder containing settings.gradle.kts.
  2. Select JDK 17 or 21 as the Gradle JDK under Settings → Build, Execution, Deployment → Build Tools → Gradle.
  3. Sync Gradle and install SDK Platform 35 and Build Tools 35.0.0 if prompted. The first sync needs internet access.
  4. Select an Android 6.0+ phone or emulator and press Run.

Windows build and checks:

.\gradlew.bat testDebugUnitTest assembleDebug lintDebug

macOS/Linux: run chmod +x gradlew, then use ./gradlew with the same tasks. Included toolchain: Kotlin 2.1.20 · AGP 8.9.2 · Gradle 8.11.1.

Under the hood

Small, native, self-contained.

Android Canvas renders the court and players. Native touch input handles movement and shots. Gameplay needs no account, network permission, WebView, or third-party game engine.

RallyEngine.kt
Movement, AI, shot timing, scoring, and match state.
RallyView.kt
Court graphics, multi-touch controls, haptics, and saved best rally.
MainActivity.kt
Android Activity and pause/resume lifecycle.
RallyEngineTest.kt
Four tests covering pause, shot timing, returns, and match reset.

Validation status
Kotlin sources compiled against Android Studio’s layout library, and all four logic tests passed. APK assembly, Android lint, and device gameplay remain unverified because local SDK access was blocked.

Accessibility limitation: the Canvas controls do not expose individual TalkBack actions.
